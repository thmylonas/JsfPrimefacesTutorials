CDI Named beans to be available we need the dependency: "javax/javaee-api":
<dependency>
    <groupId>javax</groupId>
    <artifactId>javaee-api</artifactId>
    <version>7.0</version>
</dependency>

The "javax/javaee-api" dependency, contains the "javax.inject/javax.inject", so, the next dependency is not needed:
<dependency>
    <groupId>javax.inject</groupId>
    <artifactId>javax.inject</artifactId>
    <version>1</version>
</dependency>

About the "action" attribute
--------------------------------

If in "h:commandButton" we do not use "f:ajax", everytime we press the "h:commandButton" the whole page will be loaded.
<h:form>
    <h:inputText .../>
    <h:commandButton action="#{backingBean.method}" .../>
</h:form>

Problem 1
-------------
If we don not follow the next solutions, this:
<h:form>
    <h:inputText .../>
    <h:commandButton action="#{backingBean.method}" .../>
</h:form>
without "f:ajax" inside <h:commandButton>, will lead to the:
"The origin server did not find a current representation for the target resource or is not willing to disclose that one exists."
This:
<h:form>
    <h:inputText .../>
    <h:commandButton action="#{backingBean.method}">
        <f:ajax>
    </h:commandButton>
</h:form>
is not causing this error.
A possible explanation is that:
Everytime we press the "h:commandButton" the whole page will be loaded, but the page cannot be found, because the JSF view
is not in directories under the "webapp" directory.

Problem 2
-------------
If we don not follow the next solutions, this:
<h:form>
    <h:inputText .../>
    <h:commandButton action="#{backingBean.method}" .../>
</h:form>
without "f:ajax", in every page reload the JS alert message appears:
"The page that you're looking for used information that you entered. Returning to that page might cause any action you
took to be repeated. Do you want to continue?"
A possible explanation is that:
Everytime we reload the page, with the load of the page the form is re-posted.

Solutions
-------------

JSF views have to be in directories under the "webapp" directory
--------------------------------------------------------------------
The JSF can work fully (display page, invoke BackingBean methods from "action" attribute by EL) ONLY if the JSF views
are in directories under the "webapp" directory.
If the JSF vies are in directories under the "WEB-INF" directory, then the only that will work from JSF is to display the
page only. Other more deep in JSF functionalities (like invoke the BackingBean methods from "action" attribute by EL)
WILL NOT work.

FacesServlet have to render the JSF views (not DispatcherServlet)
---------------------------------------------------------------------
Spring Controllers must not resolve the views (that means that DispatcherServlet must not be involved).
JSF views have to be found by FacesServlet, after they are put in directories under the "webapp" directory.
We can use Filters to filter the URI the client types, and transform it to the real path to the JSF view.

When the "action" attribute method is invoked (A)
-----------------------------------------------------

The "action" attribute method is invoked (due to all the following solutions are applied), using
or:

@Component(value = "exampleBackingBean")
//@Scope(value = WebApplicationContext.SCOPE_SESSION, proxyMode = ScopedProxyMode.TARGET_CLASS)
//@Scope(value = WebApplicationContext.SCOPE_REQUEST, proxyMode = ScopedProxyMode.TARGET_CLASS)
public class ExampleBackingBean implements Serializable {
}

or:

@ManagedBean(name = "exampleBackingBean")
@RequestScoped
public class ExampleBackingBean implements Serializable {
    @ManagedProperty(value = "#{commonHtmlAttributesService}")
    private CommonHtmlAttributesService commonHtmlAttributesService;
    // In ManagedBeans the ManagedProperties have to have Getters-Setters (mandatory)
}

or:

The combination proposed by the online tutorial in the link (SpringMVC integrated with JSF_v2.2 example):
Link: http://javaonlineguide.net/2015/07/jsf-2-2-spring4-integration-example-using-spring-annotations.html

@Component(value = "exampleBackingBean")
@ManagedBean(name = "exampleBackingBean")
@RequestScoped
public class ExampleBackingBean implements Serializable {
    @PostConstruct
    private void init() { /*Initialization code*/ }
}

When the "action" attribute method is invoked (B)
-----------------------------------------------------

BackingBean methods from "action" attribute can be invoked, in all the following cases:
public String backingBeanActionMethod() {
    // Code
    return null;
}
public String backingBeanActionMethod() {
    // Code
    return "";
}
public void backingBeanActionMethod() {
    // Code
}

When the "action" attribute method is invoked (C)
-----------------------------------------------------

BackingBean methods from "action" attribute can be invoked, with whatever value of "immediate" attribute.
That means in all the following cases:
<h:commandButton ...immediate="true"/>
<h:commandButton ...immediate="false"/>
